# Engine Simulator для Roblox — Архитектура

> **Статус:** это проектный документ задуманного Roblox/Luau-порта. Текущее
> приложение — Python-симулятор; его реальная архитектура описана в
> `docs/APP_ARCHITECTURE.md`.

> Полноценный симулятор двигателя: реалистичная физика рабочего процесса,
> любые типы двигателей и топлива, визуальный конструктор с 3D-развёртыванием,
> и очень качественный звук.

---

## 0. Цели и жёсткие ограничения платформы

**Цели**
1. Реалистичная модель работы двигателя (не аркада): крутящий момент, ВСХ,
   турбо/наддув, детонация, тепловые режимы, ограничитель.
2. Полная кастомизация: цилиндры, блок, ГРМ, впуск, выпуск, наддув,
   топливная система, зажигание, охлаждение.
3. Много типов двигателей: I4/I6/V6/V8/V10/V12, boxer, роторный (Ванкель),
   2-тактный, дизель, газотурбинный/реактивный.
4. Топлива с разными свойствами (октановое число, плотность, энергия,
   стехиометрия, скорость горения, теплота испарения, температура самовоспламенения).
5. Реалистичный звук: стартер, запуск, холостой, разгон, нагрузка/сброс,
   ограничитель, отстрелы, турбо-спул, blow-off, выключение.
6. Визуальный конструктор: собрал двигатель в UI → появился в мире в 3D →
   завёл, дал газ, следишь за приборами.

**Ограничения Roblox (определяют всю архитектуру)**
- **Luau не умеет генерировать PCM в реальном времени.** Нельзя «синтезировать»
  звук покадрово. Значит звук = воспроизведение сэмплов + питч + слои + DSP.
- **Аудио-API (актуальное, 2026):** `AudioPlayer` (`PlaybackSpeed`, `Looping`,
  `LoopRegion`, `PlaybackRegion`, `Volume`, `TimePosition`), `AudioEmitter`
  (3D-затухание, `SetDistanceAttenuation`), `AudioListener`, `Wire` для соединения
  узлов, эффекты `AudioPitchShifter`, `AudioCompressor`, `AudioEqualizer`,
  `AudioDistortion`, `AudioReverb`, `AudioFilter`, `AudioLimiter` и др.
  Пиру `PlaybackSpeed` даёт одновременно и питч, и скорость — это ключ к звуку ДВС.
- **`EditableMesh` не создаётся напрямую** (`Not Creatable`): только через
  `AssetService:CreateEditableMeshAsync(...)` и `AssetService:CreateMeshPartAsync(...)`.
  Используем для процедурной геометрии деталей двигателя.
- **Физика авторитетна на сервере**, звук должен быть мгновенным на клиенте →
  звук предсказывается локально.
- Лимиты: количество звуковых движков на клиенте, бюджет сетевого трафика,
  сложность коллизий.

## 1. Высокоуровневая архитектура

Четыре слоя, каждый изолирован и не зависит от UI:

```
┌──────────────────────────────────────────────────────────────────┐
│ L4  PRESENTATION     BuilderUI · HUD · Gauges · ViewportFrame     │
├──────────────────────────────────────────────────────────────────┤
│ L3  WORLD            Deployer (сборка модели) · AudioController   │
│                      Camera/Rig · Dynamometer stand · Vehicle     │
├──────────────────────────────────────────────────────────────────┤
│ L2  SIMULATION       SimulationHost · EngineModel · subsystems    │
│                      (Thermo, Combustion, Turbo, Induction, ...)  │
├──────────────────────────────────────────────────────────────────┤
│ L1  DOMAIN / DATA    Blueprint schema · PartDefs · FuelDB ·       │
│                      LayoutDB · SoundLibrary · Units · Validate   │
└──────────────────────────────────────────────────────────────────┘
```

**Разделение ответственности клиент/сервер**

| Подсистема | Где | Почему |
|---|---|---|
| Модель двигателя (интегрирование) | **Сервер** | Античит, единая правда, генерация момента для машины/стенда |
| Сборка 3D-модели | **Сервер** (репликация) | Клиент не должен создавать физику |
| Конструктор (редактирование blueprint) | **Клиент** UI → валидация на сервере | Отзывчивый UI |
| Звук | **Клиент** | Нулевая задержка; нельзя ждать RTT |
| Предсказание звука | **Клиент** из реплицированных throttle/RPM | Сглаживание сетевых рывков |
| Приборы/HUD | **Клиент** | Отрисовка |

**Ключевое решение по звуку:** сервер реплицирует «состояние привода»
(`rpm`, `throttle`, `load`, `boost`, `backfire`, `limiter`, `temp`) с частотой
~20–30 Гц. Клиент **не ждёт** эти пакеты: он крутит локальную лёгкую модель РПМ
(предсказание по throttle + инерция) и использует серверные значения как
коррекцию. Так звук отзывчив к нажатию газа, но синхронизирован с физикой.

## 2. Модель данных: Blueprint двигателя

Двигатель = чистые данные (сериализуемый словарь). Ничего не хранится только
в Instances — Instance собирается из blueprint.

```lua
type Blueprint = {
    schemaVersion: number,
    meta: { name: string, author: number, created: number },

    layout: {
        kind: "Inline" | "V" | "Boxer" | "Rotary" | "Radial" | "Turbine",
        cylinders: number,
        bankAngle: number?,     -- для V-образных
        firingOrder: string?,   -- "1-8-7-2-..." или "auto"
    },

    block:   BlockSpec,      -- bore, stroke, compressionRatio, deckHeight, material
    crank:   CrankSpec,      -- ход, колена, маховик (inertia), балансировка
    pistons: PistonSpec,     -- диаметр, масса, кольца
    rods:    RodSpec,        -- длина шатуна (влияет на R/S ratio)
    head:    HeadSpec,       -- ГБЦ, камеры сгорания, клапаны (Ø, ход)
    valvetrain: ValvetrainSpec, -- OHV/SOHC/DOHC, распредвалы, профили, VVT/VVL
    induction: InductionSpec,   -- NA | Turbo | Supercharger; интеркулер;
                                -- длина/Ø впускных каналов (резонанс Гельмгольца),
                                -- дроссель, ресивер, фильтр
    exhaust: ExhaustSpec,       -- коллектор, равнодлинный, турбина,
                                -- катализатор, глушитель, backpressure
    fuelSystem: FuelSystemSpec, -- карбюратор | инжектор порт | прямой впрыск | дизель;
                                -- форсунки, давление, топливный насос, бак
    ignition: IgnitionSpec,     -- система, карта УОЗ, свечи, отсечка
    cooling: CoolingSpec,       -- радиатор, термостат, помпа, антифриз, вентилятор
    lubrication: LubricationSpec,-- масл. насос, вязкость, маслокулер, поддон
    electronics: ECU,           -- прошивка: карты VE/AFR/УОЗ/наддува
    fuelId: string,             -- ссылка на FuelDatabase
    redline: number,
    starterRpm: number,
}
```

Всё — числа и строки, легко валидировать, хранить в DataStore, показывать в UI.

## 3. Ядро симуляции (L2)

### 3.1 Единое состояние

```lua
type EngineState = {
    crankAngle: number,     -- рад, для послойного расчёта
    rpm: number,
    omega: number,          -- рад/с
    throttle: number,       -- 0..1
    running: boolean,
    manifoldPressure: number,
    boost: number,          -- избыточное давление, бар
    afr: number,
    egt: number,            -- темп. выхлопных газов
    coolantTemp: number,
    oilTemp: number, oilPressure: number,
    knock: number,          -- интегральный детонационный индекс
    limiterActive: boolean,
    fuelLevel: number,
    health: number,
}
```

### 3.2 Уравнение движения коленвала (базовое)

```
J · dω/dt = T_indicated(θ, …) − T_friction(ω) − T_pumping(θ, …) − T_load
```

- `J` — момент инерции (коленвал + маховик + нагрузка).
- `T_friction` — модель Чена-Флинна: `a + b·ω + c·ω²` (трение, насосные, генератор).
- `T_load` — внешняя нагрузка (стенд, трансмиссия, гидротормоз дино).

### 3.3 Модель горения (реализм)

Три уровня точности; переключаются флагом «реализм».

1. **Mean-value (быстро):** `T_engine = MAP(rpm, throttle) · f(нагрузка, температура)`.
   Идеально для аркадного режима и для мобильных.
2. **Map-based (средне):** VE-карта (объёмный КПД) строится из геометрии
   (длина впускных/выпускных, фазы ГРМ, наддув). Крутящий момент =
   `η · m_dot_air · AFR_stoich/λ · LHV · (1 − потери)`. Учитывает
   наполнение и топливную энергию.
3. **Cycle-based (максимум):** по углу поворота КВ, послойно/по цилиндрам.
   Тепловыделение по функции Виббе `x(θ) = 1 − exp(−a·((θ−θ0)/Δθ)^(m+1))`.
   Давление в цилиндре → индикаторная работа → момент. Позволяет честно
   моделировать **детонацию**, **перекрытие клапанов**, **резонансный наддув**,
   **лаг турбины**.

Реализация: внутренний шаг `dt_sim = 1/360` секунды (или подшаг по θ),
вызывается из `Heartbeat` (60 Гц) несколькими итерациями на кадр.

### 3.4 Подсистемы (каждая — отдельный модуль, чистая функция)

| Модуль | Отвечает за |
|---|---|
| `Thermo` | идеальный газ, плотность воздуха от T/P, энергия топлива |
| `Combustion` | функция Виббе, скорость фронта пламени, детонация |
| `VolumetricEfficiency` | наполнение от rpm, фаз ГРМ, длины каналов |
| `Induction` | **резонанс Гельмгольца** впускных труб → «полки» момента |
| `Exhaust` | противодавление, продувка, влияние на EGT |
| `Turbo` | энергия выхлопа → скорость крыльчатки → буст → **лаг**; wastegate; BOV |
| `Supercharger` | механический наддув, прямая связь с rpm, паразитная мощность |
| `FuelSystem` | подача, λ, обеднение/обогащение, ограничение форсунок |
| `Ignition` | УОЗ, отсечка по RPM (fuel cut / ignition cut), «bounce» |
| `Cooling` | тепловой баланс радиатор ↔ двигатель, термостат, перегрев |
| `Lubrication` | вязкость от T, давление, масляное голодание |
| `Damage` | износ от детонации/перегрева/перекрута → `health` |

### 3.5 Реалистичные «фишки», которые делают симулятор живым

- **Резонансный наддув:** подбор длины впускного канала даёт горб момента.
- **Турбо-лаг:** визуальный (стрелка буста) и звуковой (спул).
- **Детонация:** слышна как «дробь», зависит от октана, степени сжатия, буста,
  УОЗ и температуры впуска.
- **Отсечка:** не рубленая, а «блуждающая» (fuel cut + bounce RPM).
- **Отстрелы/попы:** на сбросе газа при богатой смеси + горячий выпуск.
- **Перегрев → limp mode**, потеря мощности, риск повреждения.
- **Дизель:** нет дросселя, регулирование количеством топлива, дымность.
- **Роторный:** другой цикл (4 такта за 3 оборота), свой звук и момент.
- **Турбина/реактивный:** N1/N2, EGT, лаг в секунды, звук свист/рёв.

## 4. Звуковая система (L3, клиент)

### 4.1 Принцип: слоистые луп-сэмплы + питч-трекинг + DSP

Roblox не даёт синтезировать звук, поэтому **звук = библиотека сэмплов,
управляемая процедурно**. «Реалистичность» достигается системой управления,
а не генерацией.

**Слои одного двигателя (для каждого архетипа записывается/готовится набор):**

| Слой | Назначение | Управление |
|---|---|---|
| Idle loop | холостой | `PlaybackSpeed = rpm/rpm_ref` |
| Low-load loop | малая нагрузка / сброс | кроссфейд по `load` |
| Mid loop | частичный газ | кроссфейд по rpm+load |
| WOT loop | полный газ | кроссфейд по throttle |
| Coast/overrun | торможение двигателем | при `throttle≈0, rpm высокий` |
| Limiter | отсечка | one-shot + зацикл. |
| Turbo spool | свист турбины | питч ∝ скорости крыльчатки |
| BOV pshh | blow-off | one-shot по сбросу буста |
| Wastegate flutter | «тра-та-та» | модулированный луп |
| Starter crank | стартер (вжик-вжик) | one-shot, до старта |
| Start catch | «схватил» | one-shot при переходе в running |
| Shutdown | выключение | one-shot |
| Backfire/pop | отстрелы | one-shot на событие |
| Knock | детонация | луп, gain ∝ knock |

**Как это миксуется:**
- Каждый слой — свой `AudioPlayer` (`Looping = true`, `PlaybackSpeed` = функция rpm).
- Громкости слоёв — кроссфейд-функции `w_i(rpm, load)` c сохранением энергии.
- Все `AudioPlayer` → общий микшер-узел → `AudioEmitter` на выпускном коллекторе
  (и второй на корпусе для механических шумов) → `AudioListener` игрока.
- Поверх — DSP-цепочка: `AudioPitchShifter` (лёгкий доп. питч на сбросе),
  `AudioCompressor` (нагрузка/громкость), `AudioEqualizer` (характер: «железо»,
  «турбо», «ротор»), `AudioDistortion` (на WOT/отсечке), `AudioReverb` (тоннель/гараж).
- Питч-трекинг: `PlaybackSpeed = clamp(rpm / rpm_ref_layer, 0.5, 2.0)` — вне
  диапазона слоя кроссфейдим на соседний слой, чтобы избежать «бурундука».

**Событийная шина:** `Events.luau` получает из репликации события
(`RpmLimiterHit`, `Backfire`, `BovOpen`, `StarterEngage`, `IgnitionOn`, `FlameOut`)
и триггерит one-shots со случайной вариацией (не каждый раз одинаково —
это сильно добавляет реализма).

### 4.2 Откуда берутся сэмплы (offline-пайплайн)

Roblox не умеет синтез в рантайме, но мы можем **сгенерировать качественные
сэмплы заранее** (офлайн) и загрузить как ассеты:

```
tools/soundgen/            (Python, отдельный билд-шаг, НЕ в Roblox)
    engine_synth.py        физическая модель звука ДВС:
                           импульсы сгорания (pulse train),
                           цилиндровые события по порядку работы,
                           резонансы выпуска, шум впуска, турбо-свист
    render_layers.py       рендер лупов: idle/mid/wot/coast + one-shots
    config/*.yaml          параметры по архетипам (I4, V8, rotary, diesel, jet)
    → out/*.wav            нормализация, loop-point, загрузка в Roblox
```

Это даёт «очень-очень хороший звук», полностью управляемый из Lua, при этом
без realtime-синтеза. В качестве альтернативы — лицензированные/CC0 записи,
обработанные тем же пайплайном (обработка loop-points, ресэмплинг, нормализация).

### 4.3 Почему это надёжнее «процедурки»

- Нет CPU-нагрузки на Lua в реальном времени.
- Предсказуемо по бюджету звуковых движков.
- Звук «студийного» качества, а реализм — в *управлении* (лаг, нагрузка, события).

## 5. Визуальный конструктор и 3D-развёртывание (L3/L4)

### 5.1 Конструктор (клиент, UI)

Поток: **выбор схемы → параметры → предпросмотр → сборка → валидация → деплой**.

- Панели: Layout, Block, Crank, Head, Valvetrain, Induction, Exhaust, Fuel,
  Ignition, Cooling, Tuning (карты ECU).
- Живой расчёт: любой параметр мгновенно пересчитывает кривую момента и звуковой
  профиль (на клиенте, облегчённой моделью) + показывает график ВСХ.
- Ошибки валидации: «шатун короче хода коленвала», «степень сжатия 20:1 на бензине
  → детонация», «турбина без интеркулера», «форсунки не дают нужный расход».

### 5.2 Предпросмотр

- `ViewportFrame` с `WorldModel`, вращающаяся 3D-сборка деталей.
- Геометрия деталей — из реестра `PartRegistry`: либо базовые `Part`/`MeshPart`,
  либо процедурные через `EditableMesh` (кастомные блоки/коллекторы).

### 5.3 Деплой в мир

```
Blueprint → Deployer.buildModel(blueprint) → Model в Workspace
         → SimAttachments (точки: выпуск, турбина, дроссель, дино-муфта)
         → weld к EngineStand (свободный) или к шасси (vehicle)
         → Sensors (RPM-датчик, EGT, boost) → HUD
```

- Двигатель появляется в мире как физическое тело на стенде/в машине.
- Запуск/газ: `Start` (стартер + зажигание), `Throttle` (0..1), `Choke`,
  `IgnitionOff`, `LoadBrake` (дино-нагрузка).
- Стенд: гидротормоз даёт регулируемую нагрузку → можно снимать ВСХ в реальном
  времени и смотреть график.

## 7. Сетевой протокол

**Клиент → Сервер** (`RemoteEvent`, валидируется):
`CreateEngine(blueprint)` · `Deploy(blueprint, target)` · `Start(id)` ·
`Stop(id)` · `SetThrottle(id, value)` · `SetLoad(id, value)` · `SetIgnition(id, on)`
· `Tune(id, ecuPatch)` · `Destroy(id)`.

**Сервер → Клиент:**
- `RemoteEvent` (события): `EngineReady(id, model)`, `FlameOut(id, reason)`,
  `Knock(id, severity)`, `Backfire(id)`, `Limiter(id, on)`, `Damage(id, hp)`.
- `UnreliableRemoteEvent` (телеметрия ~20–30 Гц): `{id, rpm, throttle, load, boost,
  egt, coolant, oilP, afr, fuel, health}`.

Клиент интерполирует телеметрию и **предсказывает rpm** между пакетами для звука.
