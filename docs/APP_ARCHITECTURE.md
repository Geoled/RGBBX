# Архитектура десктоп-симулятора двигателя

Это документ-источник по приложению `simulator/`. Он описывает слои, модель
физики, звук, 3D и модель потоков. Звуковой пайплайн `tools/soundgen` остаётся
отдельным и переиспользуется как есть.

## 1. Цель и рамки первой версии

Интерактивный стенд: собрать/выбрать двигатель, завести его, газовать под
нагрузкой и наблюдать, что происходит.

В первую версию входят (по выбору заказчика):

1. **Физика двигателя** — реальный расчёт момента/мощности, нагрузка, передача.
2. **Звук в реальном времени** — синтез по текущим оборотам и нагрузке.
3. **График динамометра** — момент и мощность от оборотов.
4. **Живой 3D-движок** — анимация по реальному углу поворота коленвала.

В комплекте 23 двигателя: 6 «эталонных» (рядная четвёрка NA и с турбиной,
дизель, V8 cross-plane, роторный 13B, газовая турбина), 13 добавленных позже
(рядные 3/5/6, оппозитные 4/6, V6 twin-turbo, V8 flat-plane, V10, V12,
одноцилиндровый двухтактник, Peugeot 205 GTI, Peugeot 206 GTI 180, Lexus LFA
4.8 V10) и 4 дополнительных пресета (BOSER Flat-8 2.5, YTead I6 4.0,
V12-por I12 12.5, Huge ass I3). Список с параметрами — `run.bat --list`.

Новый двигатель — это файл-пресет, который автор правит руками: шаблон со всеми
полями лежит в `presets/_template.toml`, пошаговое руководство — в
`docs/CREATING_ENGINES.md`, заготовку создаёт `python -m soundgen new <имя>`.
Пресеты, чьё имя начинается с `_` или `.`, считаются шаблонами и нигде не
находятся: единственная точка перечисления — `config.discover_presets()`.

Вне первой версии (задел на потом): UI-билдер из компонентов, диагностика и
повреждения, сохранение конфигураций.

## 2. Стек

Базовый запуск по-прежнему возможен на `numpy` + `Pillow` + stdlib. Пакеты из
`requirements.txt` включают улучшения, но почти каждый из них имеет fallback:

| задача | решение | почему |
|---|---|---|
| окно, виджеты | `tkinter` (stdlib) | есть всегда, ничего не ставить |
| 3D | свой растеризатор: numpy + `PIL.ImageDraw` | GPU-библиотек нет; замеры ниже |
| звук на выход | `sounddevice`/PortAudio, затем `winmm` | WASAPI даёт ~22 мс против ~106 мс у MME; WinMM остаётся страховкой |
| математика | `numpy` 2.5.1 + `scipy` | FFT в numpy; периодический cubic spline для питча лупов |
| WAV | `soundfile`/libsndfile, затем stdlib `wave` | корректные 24 бита и метаданные |
| громкость | `pyloudnorm` (опционально) | LUFS в манифесте для контроля ассетов |
| тесты | `pytest` | быстрые регрессии вместо только `--selftest` |

Замеры, на которых основан выбор (это не оценки, а реальные прогоны на этой
машине):

| подход | результат |
|---|---|
| numpy, попиксельный z-буфер | 504 треугольника → 24.7 fps |
| `PIL.ImageDraw.polygon`, painter's algorithm, треугольники | 2240 → **90 fps**, 5120 → 65 fps |
| то же, но грани — выпуклые n-угольники | V8: 9.0 мс → **3.6 мс** на кадр |
| `winmm` `waveOut` стриминг | 48 кГц моно 16 бит, двойная буферизация — работает |
| `sounddevice` WASAPI, block 512 | 48 кГц моно 16 бит, ~22 мс задержки; MME — ~106 мс |

Решающим оказался второй пункт: попиксельный растеризатор на numpy упирается в
накладные расходы numpy на каждый треугольник (≈68 мкс), а `ImageDraw.polygon`
заполняет треугольники в C. Поэтому 3D рисуется алгоритмом художника
(сортировка по глубине, без z-буфера). Для почти выпуклой сборки двигателя
артефактов пересечения не видно.

Что именно стоит времени — не площадь фигуры, а **число вызовов** `polygon`
(≈1–3 мкс на вызов, независимо от размера и от разрешения окна). Отсюда
третий пункт: грань — выпуклый n-угольник, а не треугольник. Куб стоит 6
вызовов вместо 12, крышка цилиндра — 1 вместо веера из 12, весь V8 — 1686
вызовов вместо 4988. Всё, что идёт до цикла отрисовки (трансформация,
отсечение задних граней, ближняя плоскость, проекция, затенение, сортировка),
считается numpy сразу по всему мешу.

## 3. Слои

Модель «снизу вверх», как в `docs/ARCHITECTURE.md`, но без Roblox.

```
  physics.py     модель двигателя и трансмиссии  (чистая математика, без I/O)
       │  rpm, load, throttle, angle
       ├──────────────► audio/    синтез звука в реальном времени
       └──────────────► view/     геометрия и анимация 3D
                              │
                        ui/app.py  окно: контролы, 3D, приборы, динамометр
```

Правила зависимостей:

* `physics.py` ничего не знает про звук, 3D и UI. Тестируется без окна.
* `audio/` и `view/` знают про `physics` только по значениям (rpm, нагрузка…).
* `ui/` — единственное место, которое знает про всё.

`soundgen` подключается как внешний пакет (см. `bootstrap.py`): приложение
использует его `EngineVoice` и `Preset`, а не копирует их.

## 4. Физика

Состояние: `rpm`, угол коленвала `theta`, давление во впускном репе `MAP`,
положение дросселя. Шаг интегрирования 0.25 мс (4 кГц) — для динамики оборотов
этого с запасом, а стоит почти ничего.

### 4.1 Баланс моментов на коленвале

```
J · dω/dt = T_ind(ω, MAP) − T_fric(ω) − T_pump(MAP) − T_load(ω) − T_starter
```

`J` — момент инерции двигателя и приведённой трансмиссии. Момент инерции
масштабируется от рабочего объёма, так что большой V8 «тяжелее» на разгон, чем
мотоциклетный мотор.

### 4.2 Индикаторный момент (то, что реально даёт газ)

Считается от массы топлива, а не «по кривой»:

```
ρ_man   = MAP / (R · T_man)                        плотность заряда
m_air   = η_v(ω) · V_цил · ρ_man                   воздух за цикл
m_fuel  = m_air / AFR                              бензин 14.7, дизель по λ
W_цикл  = η_i · m_fuel · LHV                       работа за цикл
T_ind   = W_цикл / (2π · cycle_revs)               момент; cycle_revs = 2 для 4-такт.
```

`η_v(ω)` — коэффициент наполнения, колоколообразная кривая с максимумом около
пика момента. `η_i` — индикаторный КПД (≈0.40 бензин, ≈0.45 дизель).

Важно: **кривая момента не задана вручную.** Она получается сама из наполнения,
потерь и падения давления во впуске на высоких оборотах.

Форма `η_v(ω)` по умолчанию выводится из спецификации, но её можно переопределить
в пресете (`ve_peak_rpm_frac`, `ve_droop`, `ve_peak_value`; `0` = автоматически).
Это нужно двигателям, снятым с реальных стендов: у них полка момента сдвинута к
верхам, и автоподбор её сглаживал. Значения по умолчанию оставляют калибровку
остальных пресетов нетронутой.

### 4.3 Впуск — это не константа

Отдельная модель ресивера, потому что именно она даёт правильную реакцию на газ
и «просадку» давления на верхах:

```
dP_man/dt = (R·T_man / V_man) · (ṁ_дроссель − ṁ_двигатель)
```

Расход через дроссель — стандартное уравнение истечения (с критическим
режимом), расход двигателя — `η_v · V_цил · ρ · (ω / (2π · cycle_revs))`.
Постоянная времени ресивера ≈ 18 мс на 6000 об/мин, поэтому шаг 0.25 мс
устойчив.

### 4.4 Наддув

Компрессор стоит **до** дросселя, поэтому наддув нельзя просто записать в `MAP`:
дроссель всё равно должен пропустить лишний воздух. Модель считает давление
перед дросселем `P_вх = P_атм · pr`, а `pr` и температура заряда — из степени
повышения давления и КПД компрессора:

```
pr      = (1 + boost) · 0.95                     потери в интеркулере и тракте
T_компр = T_атм · (1 + (pr^((γ−1)/γ) − 1) / 0.70)  адиабатический КПД 70 %
T_заряда = T_компр − ε · (T_компр − T_атм)        ε = 0.70, эффективность кулера
```

Без учёта нагрева двигатель «дышит горячим разреженным воздухом» и не выдаёт
заявленных сил; без потерь — выдаёт больше. Плотность берётся из `MAP` и
`T_заряда`, поэтому интеркулер реально прибавляет мощность.

* **Турбина не дует сразу.** Наддув задаётся не линейным ростом по оборотам, а
  возможностью турбины: ниже порога `spool_rpm` она нулевая, выше — выходит на
  плато (smoothstep), потому что дальше давление держит вестгейт, а не скорость.
  Фильтр первого порядка с `τ = 0.16…0.50 с` на разгон (медленнее на малой
  нагрузке: раскручивает ротор энергия выхлопа) и `0.26 с` на сброс.
* **Компрессор — это заслонка в выхлопе.** `P_выхлоп` растёт вместе с наддувом
  (`+0.9·boost`), и насосные потери съедают часть прибавки — иначе турбомотор
  получался бы линейно-идеальным.
* **Supercharger** (`kind = "supercharger"`) приводится от коленвала: `spool`
  открыт, давление есть сразу, а не через полсекунды.
* **Детонация** — не эмпирический «балл», а корреляция задержки воспламенения
  Douaud–Eyzat для остаточного газа: `tau = 17.68·(ON/100)^3.402·p^-1.7·exp(3800/T)`
  (мс, p в бар, T в K). Доступное время — окно около ВМТ на текущих оборотах,
  поэтому отношение `t_window/tau` ведёт себя как интеграл Ливенгуда–Ву: растёт
  с наддувом и степенью сжатия, падает с октановым числом и с ростом оборотов.
  При превышении порога появляется `knock_level`, датчик детонации откатывает
  угол (`knock_retard`), момент падает на величину до 30 %, а после прекращения
  детонации retard медленно восстанавливается. Октановое число задаётся в
  `[block]` (`octane`, по умолчанию 95). Дизель и турбина детонировать не
  могут — для них индекс всегда нулевой.

Проверка: `python -m simulator --selftest` сравнивает замеры с реальными
классами (BMEP 8–14 бар у атмосферника, 1.07 из 1.35 бар наддува на полной
нагрузке, ноль наддува на холостом ходу).

### 4.4.1 Газотурбинный двигатель

Турбина не является поршневым мотором, поэтому у неё отдельная mean-value
модель цикла Брайтона, а не «момент = константа × обороты». Параметры цикла
лежат в `[turbine]` пресета, а `[turbo]` продолжает отвечать только за звук.

Скорость ротора задаётся регулятором первого порядка: это то, что делает
топливный агрегат реальной турбины, — он планирует подачу топлива под
запрошенные обороты, а не интегрирует мгновенный момент. Поэтому:

* на холостом ходу цель — ровно `idle_rpm`, а не доля от красной зоны;
* стартер раскручивает ротор до скорости зажигания, после чего
  `_turbine_started` удерживает горение до выключения зажигания;
* `spool_tau_s` / `wind_down_tau_s` задают разгон и выбег;
* динамометр задаёт ту же цель оборотов, но с рампой; тормозной момент равен
  моменту на валу, поэтому кривая на графике — это реальный момент турбины.

Термодинамика считается по воздушному стандарту:

```
pr_c = 1 + (PR − 1)·(N/N_max)²              карта компрессора, PR из [turbine]
T2   = T_атм·(1 + (pr_c^((γ−1)/γ) − 1)/η_c)
m_dot = m_dot_design·N/N_max
T3   = T_idle + (T_max − T_idle)·fuel
T4   = T3·(1 − η_t·(1 − (1/(pr_c·0.95))^((γ−1)/γ)))
P    = m_dot·(c_p,газ·(T3 − T4) − c_p,возд·(T2 − T_атм))·η_мех
T    = P/ω
```

Здесь `η_c`, `η_t`, `η_мех` — адиабатические КПД компрессора и турбины и
механический КПД; `0.95` — потери давления в камере сгорания и тракте. Модель
не содержит рекуператора, регулируемого соплового аппарата и отборов воздуха,
но правильно реагирует на степень повышения давления, температуру перед
турбиной, массовый расход и КПД компонентов. Топливо считается по подъёму
температуры в камере и `LHV` керосина, поэтому `turbine_fuel_kg_s` — не
декоративная величина.

Для текущего пресета (PR 12, TIT 650/1200 °C, 15 кг/с) модель даёт около
**4.33 МВт** и **1000 Н·м** на 41 000 об/мин, то есть ~688 кВт/л при
6.28 л; на холостом ходу — около 258 кВт при 12 000 об/мин. `--selftest`
проверяет набор холостого хода, диапазон мощности, плотность мощности и
полку ниже красной зоны.

### 4.5 Потери

* **Механические** — через среднее эффективное давление трения (формула
  Чена–Флинна, а не чистая линия Уилланса):
  `FMEP(бар) = 0.70 + 0.11·(N/1000) + 0.013·(N/1000)² + 0.60·load`, момент
  трения `T_fric = FMEP·V_д / (4π)`. Член `load` — это `b·P_max`: кольца
  прижимаются к цилиндру давлением газов, и подшипники несут нагрузку
  сгорания, поэтому работающий мотор трётся сильнее, чем тот же мотор на
  частичной нагрузке. Без него модель завышает КПД на частичных нагрузках.
* **Насосные** — `T_pump ∝ (P_выхлоп − MAP)`. Именно они дают торможение
  двигателем: на сбросе газа дроссель закрыт, `MAP` падает, и потери становятся
  больше индикаторного момента — обороты падают с реальной скоростью.

### 4.6 Регулятор холостого хода, отсечка, стартер

* **РХХ** — ПИ-регулятор по оборотам, подмешивает дроссель, когда педаль
  отпущена, чтобы холостой ход держался ровно. Утечка закрытой заслонки
  намеренно мала (0.25 % площади): холостой воздух обязан приходить от
  регулятора. Иначе большой мотор — который на тот же зазор заслонки гонит
  куда больше воздуха — раскручивался бы выше уставки, а у регулятора не было
  бы полномочий сбросить обороты (именно так 12.5-литровый V12 держал 1530
  об/мин при уставке 850).
* **Отсечка** — отключение подачи топлива выше красной зоны, с гистерезисом
  (включение ниже `redline − 150`), чтобы обороты «пилили», а не залипали.
* **Стартер** — пока кнопка нажата, к коленвалу приложен момент стартера;
  топливо подаётся выше порога проворота.

### 4.7 Динамометр: поправка на инерцию

Динамометр держит заданные обороты, поэтому его тормозной момент равен моменту
мотора. Но пока целевые обороты растут по рампе (550 об/мин/с), часть момента
уходит не в тормоз, а на разгон вращающихся масс: `T_двиг = T_торм + I·dω/dt`.
Без поправки график занижается на `I·dω/dt` — около 10 % пикового момента
четвёрки, — и полка мощности выглядит слабее, чем есть. Поэтому наружу
(`brake_torque`, по которому строятся график и проверки) отдаётся собственный
момент мотора, а физический тормоз остаётся только в уравнении движения. Так же
поступают настоящие динамометры.

### 4.8 Кинематика для 3D

Положение поршня считается по точной формуле кривошипно-шатунного механизма,
включая вторичную неравномерность:

```
x(θ) = r·cos θ + √(l² − r²·sin²θ),   r = ход/2,  l = rod_ratio · r
```

Угол берётся из интеграла ω, то есть 3D, звук и физика синхронны по построению.

## 5. Звук

Источник звука — `soundgen.voice.EngineVoice`, тот же самый, что рендерит
офлайн-файлы. Ничего не переписывается ради реалтайма: он блочный и уже умеет
`set_params(rpm, load, throttle)`.

* **Нагрузка для звука** — доля от максимального индикаторного момента при
  текущих оборотах, а не положение дросселя. Так звук правильно «грузится» на
  подъёме.
* **Отстрелы** — не по таймеру, а по физике: считаются условия (сброс газа +
  высокие обороты + был заряд), и при выполнении подмешивается один из заранее
  отрендеренных вариантов отстрела. Это и есть «реалистичный просчёт».
* **Аудиопоток** — свой поток-производитель: он синтезирует блоки и отдаёт их
  в PortAudio (`sounddevice`, WASAPI) или, если PortAudio недоступен, в `waveOut`
  (двойная буферизация). Задержка настраивается числом буферов; на этой машине
  WASAPI с block 512 даёт ~22 мс против ~106 мс у MME.

### 5.1 Путь сигнала

```
впрыск/сгорание (один импульс на цилиндр; форма — от нагрузки, длительность — от оборотов)
        -> первичный выпускной раннер цилиндра
        -> перепуск (турбулентный шум, масштабированный расходом)
        -> резонаторный банк кузова      (body / plenum modes)
        -> стоячая волна трубы           (дробно-задержанный гребёнчатый фильтр)
        -> глушитель                     (ФНЧ)
выхлоп у среза трубы (шум сдвигового слоя, минуя глушитель)  -> +
впуск (шум дросселя + импульс впускного клапана, свой банк и раннеры)  -> +
механический слой A (щелчки тарелок клапанов и форсунок по углам распредвала, hiss) -> +
механический слой B (стук коренной/шатунной по срабатываниям, перекладка поршня,
                     непрерывное трение + вой цепи на половинной частоте)       -> +
турбина / турбокомпрессор (свист + whoosh; уровень привязан к наддуву)        -> +
        -> присутствие (колокол вокруг presence_hz, не полка)
        -> срез воздуха (ФНЧ в конце цепи, air_cutoff_hz / air_order)
        -> отсечка DC -> мягкий клип -> усиление
        -> свёртка с уличным IR (sparse ранние отражения + короткий хвост, unit energy)
```

### 5.2 Что именно делает звук похожим на двигатель

* **Нормировка резонаторов по каждой моде.** `resonator_kernel` нормирует пик
  каждой моды отдельно, поэтому `modes` — это форма формант, а не суммарный
  коэффициент. Без этого импульсный отклик имел пик `q·sr/(π·f)` (~350× на
  95 Гц против ~18× на 2600 Гц), и любой пресет превращался в полку +40 дБ на
  низах, за которой впуска и механики просто не было слышно.
* **Две формы импульса сгорания.** Лёгкая нагрузка — плавный «выдох», полная —
  ударный фронт (`front_gain`). Формы заранее свёрнуты с раннером каждого
  цилиндра и смешиваются поблочно по `sharp` (нагрузка + дроссель + обороты).
* **Длительность импульса следует за оборотами.** Выпускное окно занимает
  фиксированный угол поворота коленвала, то есть тем меньше времени, чем выше
  обороты. Три заранее посчитанных варианта импульса (1.0 / 0.58 / 0.32)
  смешиваются билинейно: по нагрузке — форма, по `dur = clamp(pulse_ref_rpm /
  rpm, pulse_min_scale, 1)` — длительность. Ниже `pulse_ref_rpm` импульс не
  меняется, поэтому холостой ход звучит ровно как раньше, а на верхах появляется
  тот самый «злой» верх, который иначе приходилось бы вытягивать эквалайзером.
* **Настоящий фронт импульса.** Окно атаки 0.02 мс, а не 0.15 мс: каждые
  6 дБ/окт выше `1/(2π·окно)` — это и есть «рваный» тембр вместо «гула».
* **Гребёнка как дробная линия задержки** (`dsp.CombDelay`), а не запечённый
  FIR: температура выхлопных газов (а значит скорость звука и четвертьволновый
  резонанс) растёт с нагрузкой, и задержка укорачивается на каждый блок на
  `1/sqrt(1 + formant_shift·hot)`. Отражение от открытого среза инвертируется
  (`comb_invert`), что даёт правильный четвертьволновый ряд.
* **Отдельный раннер на каждый цилиндр** (`dsp.runner_kernel`, ±`runner_spread`
  вокруг `runner_length_m`): у цилиндров разные картины отражений, и идеально
  когерентный цуг импульсов разваливается — именно так появляется «неравный»
  звук.
* **Вариация от цикла к циклу (CCV).** Ровно один отсчёт `CircularNoise` на
  каждое срабатывание: разброс амплитуды расширяет гармонические линии. Для
  цикла длина буфера равна `loop_samples // period_samples`, поэтому за петлю
  буфер оборачивается ровно один раз и петля остаётся точной.
* **Механика по углам распредвала**: каждый клапан даёт два события — отрыв
  (`350°`/`490°`, тише) и посадка в седло (`370°`/`600°`, громче), так что
  голова с `valves_per_cyl = 4` щёлкает вдвое чаще восьмиклапанной. Форсунка
  стреляет независимо от клапанов, поэтому щелчки есть и у ротора, и у
  двухтактника. У каждого цилиндра свой постоянный сдвиг (`mech_scatter_ms`) и
  своя яркость: цуг не складывается в одну и ту же волну и не гасит выхлопной
  импульс, на котором едет. Полный привод — только для 4-тактных.
* **Механика по срабатываниям** (слой B) — не случайный шум, а сетка
  срабатываний со сдвигом: коренная/шатунная пара (`impact_kernel`, `crank_hz`)
  стучит через `+14°` после ВМТ, перекладка поршня (`slap_hz`) — через `+22°`
  (и слабее на противоположной ВМТ у 4-тактных). Это и физичнее (нагрузка на
  шатун максимальна не в самой ВМТ), и снимает фазовый замок с выхлопом, из-за
  которого низы раньше частично гасили друг друга. Сверху лежат непрерывное
  трение, ограниченное полосой `friction_lo_hz..friction_hi_hz`, и вой цепи
  на половинной частоте, влитый в кластер привода. Всё это low/band-limited,
  поэтому добавляет вес, а не шипение. У турбины слой выключен, у ротора —
  только перекладка.
* **Улица, а не «комната».** Последняя линейная стадия — настоящая свёртка с
  синтетическим импульсным откликом (`dsp.outdoor_ir`): разреженные ранние
  отражения плюс короткий тёмный хвост, нормированный по энергии, с зерном по
  seed. Мокрый/сухой микшируются равномощно. Свёртка линейна и
  время-инвариантна, поэтому петля остаётся точно периодической, а
  `layers.warmup_samples` учитывает `predelay + decay`, то есть IR успевает
  отзвучать до замыкания петли.
* **Шум потока — внутри тракта** (масштабирован массовым расходом), чтобы труба
  его окрашивала, **и отдельно на срезе** (`tail_noise`) — та часть, что
  излучается сдвиговым слоем уже после глушителя и потому не глушится.
* **«Лай» на резком газе** (`transient_bark`) — единственный слой, добавленный
  *после* глушителя, поэтому перегазовка слышна сзади машины.
* **Турбина** идёт своим путём: у неё нет дискретных срабатываний, поэтому банк
  поршневых мод заменён на полосовой шейпер (шум струи падает с частотой, а не
  белый), и раскрутка/выбег имеют разные постоянные времени.

#### 5.2.1 Верхушка спектра: чтобы высокое не «выпирало»

Первый заход давал правильный тембр, но на слух верх читался как шипение поверх
мотора. Причина была не в количестве верха, а в его форме — три отдельных пика
и ровная полка до Найквиста. Что изменилось:

* **«Яркость» — колокол присутствия, а не полка.** Полка продолжает расти до
  Найквиста и поднимает шипение ровно так же, как тело звука. Теперь
  `brightness_db` — это подъём узкой области вокруг `presence_hz` с добротностью
  `presence_q` (`dsp.presence_kernel`), а сверху всей цепи стоит `dsp.air_kernel`
  — поглощение воздуха, из-за которого реальный выхлоп никогда не бывает
  плоским до 24 кГц. Спад выше 4 кГц теперь ≈ −20 дБ/окт, как в записях.
* **Шипение — не белый шум.** `hiss_kernel` — полосовой шейпер с наклоном вниз,
  ограниченный `hiss_lo_hz..hiss_hi_hz`. Ровный белый шум читается как утечка
  пара, а не как работающий механизм.
* **Впускной шум окрашен впуском, а не полкой.** Раньше широкополосный шум
  впуска был ровной полосой `band_lo_hz..band_hi_hz` (плоская «полка» до
  6.5 кГц). Именно он давал основную долю «белого» шипения: 91 % энергии в
  полосе 4–8 кГц и 97 % выше 8 кГц были его. Теперь шум проходит через **тот
  же** резонаторный банк `modes`, что и импульсы впуска (одна свёртка — оба
  фильтра запечены в одно ядро), и получает наклон `noise_tilt_db_oct`
  (по умолчанию −2 дБ/окт от `noise_tilt_hz`). Итоговый спад компонента —
  ≈ −6.5 дБ/окт, как у турбулентного потока. Уровень выровнен
  `INTAKE_NOISE_MAKEUP`, чтобы `noise_gain` сохранил смысл. Итог: суммарный
  уровень не изменился, тональность слегка выросла, а энергия выше 6 кГц упала
  на 8–16 дБ (V8 WOT: −28.7 → −40.5 дБ).
* **Шум потока — событийный.** `flow_burst` на каждое срабатывание (свой
  декоррелированный отклик на цилиндр) плюс небольшой непрерывный `flow_noise`:
  поток слышен как отдельные «пуфы» вместе с импульсами, а не как постоянное
  шипение.
* **Привод не свистит.** Шестерни и насос — шум с ФНЧ 2.4 кГц второго порядка и
  пониженным уровнем; тон «питания» на 2.7× опущен с 0.4 до 0.18. Именно он давал
  изолированный пик ровно на 2300 Гц на холостом ходу.
* **Свист турбины слышен, только когда турбина дует.** Уровень —
  `whistle_gain · (idle_whistle + (1 − idle_whistle) · spool^1.2)`; у спящей
  турбины `spool = 0`, то есть тишина. `idle_whistle` нужен только газовой
  турбине, у которой свист есть всегда.
* **Лупы `turbo_spool` и `knock` подмешиваются непрерывно.** Это не one-shot:
  бесшовный период хранится в `EngineAudio` и читается с дробным курсором.
  Громкость и скорость чтения `turbo_spool` следуют за `boost`, а `knock` — за
  `knock_level` (чем сильнее детонация, тем чаще «пинги»). Для `turbo_spool`
  используется периодический `scipy.interpolate.CubicSpline`, чтобы питч-шифт
  не давал линейных «образов»; `knock` читается линейно, чтобы не сгладить
  транзиенты. Гейны сглажены, чтобы переход по газу не щёлкал.

Проверка: `python -m soundgen selftest` (в том числе точная периодичность петли,
шов на −164 дБ ниже сигнала) и `python -m soundgen bench`. Спектр проверялся
октавными полосами и поиском узкополосных пиков: пик считается дефектом, только
если он не кратен частоте срабатывания (в пределах 0.6 %) и имеет `Q > 20`.
Все 23 пресета чисты на холостом ходу, в крейсере и на полном газу.

Синтез одного голоса на 48 кГц идёт со скоростью 3.4–8.9× реального времени
(`block 512`; самый тяжёлый пресет — V12, ~3.4×, ~30 % ядра; большинство —
11–23 %). На 96 кГц — 1.3–2.3×. Смешивание импульсов по оборотам стоит примерно
10 %, но кэш по ключу `(sharp, dur)` пропускает пересчёт, когда двигатель
работает в установившемся режиме. Остаётся запас на 3D и физику.

## 6. 3D

* **`mesh.py`** — `Mesh`: общий пул вершин, выпуклые грани (плоский массив
  индексов + смещения граней) и цвет на грань. Примитивы: призма с переменным
  по кольцу радиусом (цилиндр и ротор Ванкеля — один и тот же вызов),
  параллелепипед, кольцо, диск. Геометрия собирается процедурно из параметров
  двигателя, а не грузится из файла.
* **`raster.py`** — проекция, отсечение, сортировка по глубине, плоское
  затенение по нормали, отрисовка `ImageDraw.polygon` в `PIL`-изображение.
  Трансформация, отсечение задних граней, ближняя плоскость, проекция,
  отбраковка субпиксельных граней, затенение и сортировка считаются numpy
  векторно; в Python остаётся только цикл вызовов `polygon`.
* **`engine3d.py`** — сборка модели из спецификации блока: блок цилиндров,
  поршни, шатуны, коленвал, распредвал, клапаны. Позиции считаются из `theta`.
  Схемы различаются: рядные, V и оппозитные — клапанный узел и логи впуска и
  выпуска; двухтактник — закрытый оребрённый цилиндр с настроенной
  расширительной камерой и карбюратором вместо клапанов; ротор — корпус
  Ванкеля с эксцентриковым валом; турбина — свой корпус с камерой сгорания.
  Логи впуска и выпуска разнесены по разные стороны, чтобы стороны читались
  с одного взгляда.

Ограничения приняты сознательно: painter's algorithm вместо z-буфера, плоское
затенение без текстур, нет настоящих теней — только мягкая контактная тень под
моделью (стопка концентрических эллипсов, цвет интерполируется от фона, поэтому
на светлом вьюпорте нет чёрной дыры). Для стилизованной механической сборки это
даёт чистое читаемое изображение при 60+ fps.

## 7. Интерфейс

Окно 1206×866 собрано из пяти карточек: шапка (44), 3D-врезка (700×440) и
приборы (476×440) в одном ряду, график динамометра (1206×176), карточка
управления (1206×156).

* **Всё рисуется Pillow.** Каждая панель — это изображение, которое кладётся в
  `PhotoImage` на голом `tk.Canvas`. Tk владеет только окном, привязками клавиш
  и выпадающим меню выбора двигателя. Причина простая: виджеты tkinter нельзя
  покрасить под Windows 11 (мягкие карточки, вдавленные канавки, скругления),
  поэтому слайдеры, кнопки, переключатели и поле выбора нарисованы вручную и
  вручную же проверяются на попадание курсора (`<ButtonPress-1>`,
  `<B1-Motion>`, `<ButtonRelease-1>`, `<Motion>`).
* **`ui/theme.py`** — палитра и поверхности. Дорогое (фон, кожа карточки,
  вдавленная канавка, кнопка, ручка слайдера) считается один раз и лежит в
  `lru_cache`; на кадр остаётся только то, что действительно меняется.
* **Приборы** — два кольцевых циферблата в стиле Fluent (тонкая дуга по светлой
  дорожке, красная зона, число в центре) плюс четыре полосы (дроссель,
  разрежение, нагрузка, момент) и три строки статистики (наддув, мощность,
  пиковый момент). Пиковый момент — это паспортная величина модели, с которой
  живой момент удобно сравнивать.
* **Дино** — сетка, заливка под кривой момента, кривая мощности вторым цветом,
  метка красной зоны, подпись пиков на своей плашке (чтобы не спорить с
  кривыми) и полоса прогресса во время прогона. Перерисовывается только тогда,
  когда меняется подпись состояния, — это самая дорогая панель.
* **3D-врезка** вставлена в карточку, обрезана скруглённой маской и залита
  светлым градиентом. Тень модели — не чёрный эллипс (на светлом фоне он
  выглядит дырой), а стопка концентрических эллипсов, цвет которых
  интерполируется от фона к цвету тени.
* **Типографика**: Segoe UI Variable → Segoe UI → Arial → DejaVu.

Частота перерисовки разделена: 3D — каждый кадр, приборы — каждые 2 кадра,
шапка — каждые 6, дино — по изменению, контролы — по событию мыши.

## 8. Потоки и синхронизация

| поток | что делает | частота |
|---|---|---|
| главный (Tk) | физика, отрисовка 3D, виджеты | 60 Гц |
| аудио-производитель | `EngineVoice.process()` → PortAudio/WinMM | по заполнению буферов |

Физика живёт в главном потоке, потому что она дешёвая (шаг 0.25 мс, но это
простая арифметика) и потому что от неё зависят и 3D, и звук. Обмен между
потоками — только через пару «снимок параметров + очередь одноразовых
событий», под одним `threading.Lock` на короткое время.

Одноразовые звуки (отстрел) кладутся в очередь; аудиопоток забирает их и
подмешивает в текущий блок. Так главный поток никогда не блокируется на звуке.

## 10. Как проверяется

* `python -m simulator --selftest` — проверки физики без окна и звука: холостой
  ход держится, пик момента и мощности в разумном диапазоне, отсечка работает,
  сброс газа даёт правильную скорость падения оборотов, шаг устойчив, наддув
  выходит на предел вестгейта под нагрузкой и равен нулю на холостом ходу.
  Каждый пресет проходит масштабно-независимые проверки (BMEP, кВт/л, полка
  мощности ниже отсечки), а также проверяются темп дино-разгона, реальное
  отключение зажигания, сброс наддува (blow-off) при сбросе газа, появление
  детонации на низких оборотах под наддувом, откат угла и его восстановление,
  а также подмешивание лупов `turbo_spool` и `knock`.
* `python -m simulator --list` — таблица всех 23 пресетов: объём, схема, тип
  топлива, диапазон оборотов.
* `python -m simulator --render-png out.png` — рендер кадра 3D в файл, чтобы
  можно было посмотреть геометрию без открытия окна.
* `python -m simulator --render-montage out.png` — по кадру на каждый пресет,
  одной таблицей (так собирается `docs/preview/montage.png`).
* `python -m simulator --capture out.png` — кадр всего окна без экрана: панели
  и так уже изображения Pillow, поэтому захват экрана не нужен.
* `python -m simulator --audio-backend winmm|sounddevice --audio-device N` —
  выбрать выход; по умолчанию `auto` берёт WASAPI-устройство с малой задержкой
  и откатывается на WinMM.
* `python -m pytest` — быстрые регрессии: свёртка против прямой, 24-битный WAV,
  влияние октана на детонацию, cubic-интерполяция турбо-лупа.
* `python -m soundgen selftest` (из `tools/soundgen`) — целостность всех
  пресетов, ровность петли (шов ниже сигнала на ~164 дБ), рендер WAV.
* `python -m soundgen bench --preset presets` — запас по реальному времени на
  каждый пресет; всё, что ниже 2×, считается проблемой.
* `python -m soundgen new <имя>` — создать заготовку пресета из шаблона.

## 11. Бюджет кадра

Замеры на этой машине, вьюпорт 680×424. Рендер — самая дорогая стадия, поэтому
именно его сокращение в 2.5 раза и позволило поднять цель с 34 до 60 fps.

| двигатель | граней | ≈ треугольников | `update`+`build` | рендер |
|---|---|---|---|---|
| I4 бензин / дизель / турбо | 952 | 2524 | 0.32 мс | 2.0 мс |
| Rotary 13B | 192 | 612 | 0.03 мс | 0.9 мс |
| Gas Turbine | 414 | 948 | 0.03 мс | 0.9 мс |
| V8 6.0 — худший случай | 1686 | 4524 | 0.59 мс | 3.6 мс |

Остальное на кадр: физика 0.6 мс, склейка вьюпорта ≈0.5 мс, приборы 0.7 мс
(перерисовываются каждые два кадра), график дино 2.0 мс — но только когда он
действительно изменился, контролы — по событию мыши. Звук синтезируется в
отдельном потоке (1.5–2.4 мс на блок в 512 кадров, то есть 4.5–7× запас по
реальному времени) и от частоты кадров не зависит: 0 недоборов буфера, 43 мс
задержки — и при 34, и при 60 fps, на всех девятнадцати пресетах.

Для сравнения, до перехода на n-угольники: V8 — 4988 треугольников, рендер
9.0 мс, окно держало 33 fps. Сейчас — 1686 граней, 3.6 мс, 56–57 fps на всех
пресетах, включая V8.
